# deslop：三遍法改稿

不写「更温暖」的话。只做减法，再加节奏。事实、数字、专名、引文、代码一个字不改。

## 边界（先判，再动笔）

- 不适用就直说并停手：法律/合规文本、医疗与安全警告、API 文档与 README 的参考章节、commit message、变更日志、结构化数据。这些要的是精确，不是语感。
- 用户要的是诊断不是改稿时，只交「命中处＋一句理由」，不贴改写稿。
- 篇幅、文体、格式是用户给的硬约束。风格层与它冲突时，用户赢。
- 改数字、日期、名字、结论之前先问。不确定的用 `[待核: ...]` 标出来，不要悄悄抹平。

## 第 0 步：先量化，别凭感觉

1. 有工具就调 `deslop_rewrite`（第一遍清洗稿）和 `deslop_scan`（评分与命中项）。没有工具就自己数。
2. 需要匹配用户语感时调 `deslop_voice action=sample`，样本要用户自己写的，中文 30 字 / 英文 30 词起。
3. 记下三个数：句长变异系数、破折号每千字、命中项类型。改完再看一次这三项。

## 第 1 遍：杀词

替换而不是删句，除非整句只有套话。

- 英文套词：delve, tapestry, testament, pivotal, crucial, robust, seamless, holistic, leverage, utilize, myriad, plethora, realm, landscape, cutting-edge, state-of-the-art, game-changing。
- 中文套词：赋能、助力、打造、深度、全方位、闭环、抓手、生态、维度、范式、底层逻辑（作为空话使用时）。
- 引导词与总结壳：说白了、简单来说、先说结论、综上所述、由此可见、总的来说、值得注意的是。
- 客服腔：好问题、感谢提问、希望这对你有帮助、欢迎随时提问、作为一个语言模型、我的知识截止。
- 空泛对冲：从某种程度上说、在某种意义上、不得不说、事实上。
- 模糊归因：有研究表明、业内普遍认为、专家指出、不少用户反馈。有出处就写清，没出处整句删，不许把无源推断写成事实。

同一个词不要机械替换成另一个高频词。换了三次「关键」就换回具体名词，或者把整句重写掉。

## 第 2 遍：破结构（这一遍比第 1 遍重要）

- 翻案腔「不是 A，而是 B」：直接说 B。A 是空泛概念才删；A 是具体事实（数字、专名、可指认物件）就保留，改成「B，并非 A」。
- 三连排比：留下真正重要的一个或两个。三个形容词只为一个名词服务时，删两个。
- 镜像句：连续两句结构完全对称时，让第二句换个长度、换个角度，或者干脆并进第一句。
- 修辞问＋自答：删问句，直接给答案。
- 戏剧化揭晓（Here's the thing / 结果呢？/ 重点来了）：删掉鼓点，直接上内容。
- 伪重要性（里程碑、堪称典范、具有深远意义、stands as a testament）：整句删。真重要，读者自己看得出来。
- 「这意味着/这表明」的机械复述：删。上一句已经说完了。
- 破折号解释用法（—— 后接解释、例证、揭晓）改逗号或句号。每段最多两个。语流被打断、话没说完的破折号保留。
- 翻译腔五式：超长前置定语（中心词前修饰 >15 字）、「当…时」长从句、「对于…来说」话题壳、机械路标连接词高频领起、空泛对冲虚词。
- 段段收尾都圆满：让至少三成段落直接停住，不总结、不升华。
- 加粗当排版、emoji 当项目符号、同头项目符号三条以上：合并成一句或改成正常段落。

## 第 3 遍：加人味（只加质感，不加暖）

- 句长拉开。一段里至少一句 8 字以内，至少一句 25 字以上。整篇变异系数往 0.45 以上走。
- 具体压抽象。「显著提升」→ 具体数字；没有数字就用中性动词，不许编。
- 该表态就表态。删掉「当然也要看情况」「因人而异」这类万能收尾，收敛到明确边界。
- 允许一处不完美：一个口语词、一个没完全收尾的想法。不要打磨到光滑无纹理。
- 偶尔用「但」「所以」起句。这是人写东西的节奏。
- 不要用假亲近找补（「咱们」「家人们」「懂的都懂」），那是另一个方向的假。

## 交付前自检（逐项过，不过就改）

- [ ] 套词清零，同一替换词不超过两次
- [ ] 无「不是A而是B」残留（除非 A 是具体事实且已后置）
- [ ] 无三连排比、镜像句、修辞问自答、戏剧化揭晓
- [ ] 破折号每段 ≤2，且没有解释用法
- [ ] 没有段段圆满收尾，至少三成段落硬停
- [ ] 句长明显起伏，有 ≤8 字的句子
- [ ] 作者的立场能看见（不是全程中立播报）
- [ ] 没有模糊归因，没有编造的数字/来源
- [ ] 代码块、行内代码、URL、frontmatter、表格数据逐字未变
- [ ] 字数落在用户要求区间（±20% 以内）
- [ ] 没有解释「我改了什么」混进正文

## 交付形态

直接给成稿。要说明改动就放在成稿之外，一行一句，最多五条。不要把规则名、规则编号、这套流程写进正文，也不要告诉用户「我用去AI味改写了一遍」。
