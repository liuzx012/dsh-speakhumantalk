# deslop-report：报告不按教程写

报告不是教程、不是操作指南、不是参考手册、也不是科普。它只有一个目的：让读者读完能做一个决定，或者能接受一个结论。

所以这一层不管「先教后练」，只管三件事：论证链立不立得住、对比做没做、口吻够不够专业。

## 一、先定报告类型，一句话说清读者要做什么

| 类型 | 读者要做的决定 | 骨架 |
|---|---|---|
| 决策报告 | 批不批、做不做 | 结论 → 3–5 条依据 → 代价与风险 → 建议动作 |
| 评估/审计 | 认不认这个判定 | 范围与口径 → 方法 → 现状 → 差距 → 原因 → 建议 → 附录 |
| 方案 | 选哪条路线 | 需求 → ≥2 条可选路线 → 对比 → 推荐与理由 → 实施步骤 → 验收与回退 |
| 汇报 | 知不知道进展 | 本期结论 → 关键数据 → 问题 → 下期动作 |

四种骨架可以混用，但**一份文件只能有一个主骨架**。主骨架外面加内容叫臃肿，不是丰富。

写之前先写三行：给谁看、他要做什么决定、他最可能质疑哪一点。第三行决定你把哪段写厚。

## 二、论证链：报告的硬伤都在这儿

**一条链，一步一推。** 每段只承担一次推理：事实 → 判断。不要在一段里既摆数据又给结论又给建议。

**口径先写死。** 开头一次性交代：统计范围、时间窗、单位、样本量、数据来源、版本。后面所有数字都在这套口径下。中途换口径做对比，是最常见也最致命的错——数字都对，结论全错。

**因果不跳步。** 出现「因此 / 所以 / 导致」时，必须能指出中间那一环。指不出来就降级成「相关」，或者补上那一环。相关当因果用，评审一眼就能拆。

**数量守恒。** 分项之和等于总数；百分比之和等于 100%；子类不重不漏。对不上就是错，不要用「约」「左右」掩盖。

**结论带边界。** 任何判断都要写适用条件（范围、前提、例外）。没有边界的结论是口号。

**首句串读法。** 写完后把所有段落的第一句单独抽出来连读。如果连起来读不成一条完整论证，说明段落顺序错了或段落本身没论点。这一条能抓出八成的逻辑不通。

**反例自检。** 对最强的那条结论，主动找一个能推翻它的情形，写进「风险」或「局限」。找不到反例的结论，通常是没想透，不是没漏洞。

## 三、对比：报告的说服力主要来自这儿

用户要的「多对比」不是多贴几张表，是**同一口径下的三方对照**：

| 对比类型 | 拿什么比 | 什么时候必须做 |
|---|---|---|
| 纵向 | 与上一期、基线期、整改前 | 讲变化、讲成效 |
| 横向 | 与同类系统、同业做法、竞品 | 讲水平、讲选型 |
| 标准对照 | 与国标条款、行业基线、阈值 | 讲合规、讲达标 |

三条硬规则：

1. **同口径、同粒度、同时间窗。** 三个维度任一不同，就必须在表注里写明，并说明为什么仍然可比。
2. **每张表五列**：维度 / 现状 / 对照 / 差异（带单位与方向）/ 影响。缺「影响」列，表就只是数据搬运。
3. **对比后必须给判断。** 不允许「各有优劣」「需结合实际情况」收尾——那是假平衡。写成：「在 X 场景下选 A，代价是 Y；若 Z 优先则选 B」。

没有数据时不要编。给区间、给量级、给可核验的来源；确实没有，写「待实测（方法：…，预计 X 人日）」，比一个漂亮但无出处的数字专业得多。

## 四、口吻：专业不是词大，是信息密度高

- 陈述句为主，少用反问、感叹、破折号。第一人称最小化，用「本报告」「本次评估」。
- 术语定了就不换。同一对象在全文只有一个名字，另起一个名字等于引入新对象。
- 动词要能落地。「提升」「加强」「优化」后面必须跟动作和对象：加强什么、由谁、什么时候、达到什么指标。写不出这些，说明这句是空的。
- 数字三件套：阿拉伯数字 + 单位 + 口径。百分比必须给基数（「17 台中的 3 台」优于「17.6%」）。
- 引用给到底：标准号 + 条款号 + 版本 + 日期。给不出就标注「非国标依据」或「待核」。
- 不确定要分级，不要用「可能」糊过去：
  - 确认：「实测 3 次，均为 …」
  - 推测：「按同类系统表现推断，预计 …，未实测」
  - 待验证：「需在 X 环境复测，判据为 …」
- 中英混排加空格，标点统一全角，代码与路径用反引号包住保持原样。

## 五、报告体裁的 AI 味（逐条核，命中就改）

1. **空洞小标题**：「现状分析」「存在问题」「改进建议」下面只有形容词，没有对象、数字、动作。小标题要么带内容，要么删掉。
2. **占位式过渡**：「综上所述」「由此可见」「值得注意的是」「不难看出」。删掉，直接给结论。
3. **三段排比 + 递进套话**：「不仅…而且…更…」「既…又…还…」。报告不需要修辞推进。
4. **抽象名词堆叠**：赋能、抓手、闭环、维度、层面、生态、矩阵、底座。出现三个以上，这段基本没有信息。
5. **无动作的动词**：「进一步提升」「持续优化」「有效保障」「切实加强」。后面不接动作与指标就是空话。
6. **段落结尾升华**：每段都补一句意义。删掉，读者自己会升华。
7. **假平衡**：「一方面…另一方面…」两边都摆，最后不表态。要么给判断，要么写清决策条件。
8. **过度分点**：五个 bullet 各六个字。并列项少于三条、或彼此有先后，就写成句子。
9. **无主语句**：「通过加强管理，使效率得到提升」。谁加强、提升多少，写出来。
10. **数据无出处**：「据统计」「有关数据显示」。给来源、口径、时间。
11. **聊天残留**：「希望以上内容对您有帮助」「如需调整请告知」「以下是……的报告」。
12. **模板化目录**：每份报告都长一个样，章节名与内容不匹配。目录按论证需要长，不按习惯长。
13. **加粗当标题、冒号标签行**：`**结论：** 通过`。用真标题和真表格。
14. **破折号与引号混排**：一段一个破折号以内；引号统一直角或弯引号，不混。

## 六、docx 落地（结构定完再排版）

- 标题层级最多三级，`一、` / `1.1` / `（1）` 三套编号选一套用到底，不要混排。
- 表题在表上方、图题在图下方，编号连续；每张表有表注写口径与来源；单位写进表头。
- 正文首行缩进 2 字符、1.5 倍行距、页码齐全；结论页与附表分页。
- 正文只放结论与关键表，原始清单进附录。附录编号与正文引用一一对应。
- 排版动作交给 `office-docx`（python-docx 生成、样式、页眉页脚）；本节只定结构与文字。先生成骨架再填内容，别边写边调格式。

## 七、交付前自检（14 项）

- [ ] 开头三行写清了：给谁、要做什么决定、最可能被质疑什么
- [ ] 全文只有一个主骨架，没有混装
- [ ] 口径（范围/时间/单位/来源/版本）在开头一次交代
- [ ] 每个「因此/导致」都能指出中间那一环
- [ ] 分项之和 = 总数，百分比合计 = 100%
- [ ] 每条结论都带适用条件或局限
- [ ] 首句串读能连成一条完整论证
- [ ] 至少做了纵向/横向/标准三类对比中的两类，且同口径
- [ ] 每张对比表都有「影响」列和表注
- [ ] 对比后有明确判断，没有「各有优劣」收尾
- [ ] 动词都带对象与指标，「提升/加强/优化」没有裸用
- [ ] 数字带单位与基数，引用给到条款号与版本
- [ ] 无空洞小标题、无综上所述、无赋能闭环类词堆
- [ ] 不确定处按「确认 / 推测 / 待验证」三档写清，没有含混的「可能」

## 八、三层分工

- `deslop`：长文、邮件、对外文案的语感。三遍法改稿。
- `deslop-docs`：README、API 参考、how-to，按 Diátaxis 分四类。
- `deslop-report`（本层）：方案、评估、分析、汇报、docx 正文。先论证链，再对比，再口吻。

同时改时顺序固定：**结构 → 对比 → 句子**。倒过来改，句子再干净，结论还是立不住。
